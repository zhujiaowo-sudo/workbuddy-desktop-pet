# WorkBuddy 专用桌宠首版设计

日期：2026-10-27

范围来源：用户已选择 WorkBuddy 专用桌宠，并指定 GitHub 仓库 `zhujiaowo-sudo/workbuddy-desktop-pet`。本设计将此前讨论的状态动画、等待确认与完成提醒、点击唤起细化为可验证的首版。

状态：用户已确认直接开发。首版实现与主要 Hook 实机联调已完成；审批、失败及子任务的额外事件验证见 `docs/compatibility.md`。

## 1. 产品范围

目标平台为 Windows 11 / Windows 10 x64。面向本机已安装并登录的 WorkBuddy 桌面版。

首版提供：透明角色悬浮窗、拖动及位置记忆、托盘、七种工作状态、断连提示、等待确认与完成提醒、点击唤起 WorkBuddy。主界面使用中文。

首版不提供：代替用户批准工具操作、聊天、Token 统计、账户额度、具体会话深链、云同步、远程控制、Codex 兼容。没有可靠数据接口的能力不显示推测数字。

初始角色为独立程序绘制的基础形象；架构预留本地动画资源包。白龙项目人物素材不随新仓库发布。

## 2. 方案选择

比较了两个方向：

1. 在白龙桌宠上直接替换 Codex 适配层：现有 Windows 窗口和动画较丰富，但与 Codex 会话、额度和读取能力关联较多，还需要逐项确认所复用代码及素材的许可。
2. 独立实现 WorkBuddy 事件适配与精简 Windows 桌宠：借鉴已有项目的模块划分和交互，首版范围更清楚，测试和后续维护不依赖 Codex 实现。

首版采用第二种方案。参考已有 WorkBuddy 桌宠的事件接入设计，不直接把其 macOS 原生窗口部分当作 Windows 成品。

## 3. 架构与技术

Python 3.12+，PySide6 6.8 至 7.0 之前的版本，pytest，PyInstaller。具体依赖版本在实现时锁定，并通过 Windows CI 验证。

模块边界：

- `workbuddy_pet.events`：事件白名单投影、大小限制与校验，不导入 Qt。
- `workbuddy_pet.state`：纯状态转换、会话汇总、提醒去重，不执行 I/O。
- `workbuddy_pet.spool`：本机事件队列的写入与增量读取。
- `workbuddy_pet.integration`：插件配置生成、安装备份、卸载与兼容性诊断。
- `workbuddy_pet.windows`：WorkBuddy 可执行文件定位和窗口唤起。
- `workbuddy_pet.ui`：悬浮窗、基础角色绘制、托盘、设置与提醒。
- `workbuddy_pet.cli`：在加载 Qt 之前分流 `--hook`、`--diagnose` 和桌宠启动模式。

用户数据放置于 `%LOCALAPPDATA%/WorkBuddyDesktopPet`。正式打包采用目录式分发，避免每次 Hook 调用都解压整个 Qt 运行时。

## 4. WorkBuddy 接入与真实能力验证

官方资料确认存在 Hook 插件类型；CodeBuddy CLI 的事件清单仅作为候选参考。必须实测当前 WorkBuddy 桌面版本。

候选事件包括 `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`PostToolUseFailure`、`Notification`、`PermissionRequest`、`Stop`、`SessionStart`、`SessionEnd`、`SubagentStart`、`SubagentStop`。

接入步骤：先用合成输入验证采集程序；再由用户发起简单任务，采集白名单字段，确认收到事件、时间、会话关系和工具生命周期。写出兼容性记录，区分实测支持、未触发与未验证。

Hook 适配器只输出本机结构化状态事件。它不得返回允许、拒绝或阻断决策；失败时正常退出，不阻断 WorkBuddy 原任务。

插件采用 WorkBuddy 支持的正式插件结构。确切清单格式、命令调用方式和重新加载方式在兼容性验证任务中确定，验证成功后才提供安装入口。

安装或卸载只修改本插件拥有的配置，先保存备份并原子写入，保留其他 Hook、插件和用户设置。卸载后恢复原有配置或移除本插件条目，不覆盖用户在安装后新增的内容。

## 5. 事件协议与数据边界

事件 schema 版本为 1。字段为 `schema`、`id`、`at`、`session_id`、`kind`，以及可选的 `parent_session_id`、`turn_id`、`tool_call_id`、`tool_category`、`notification_kind`。可选标识只有在目标版本实际提供时才投影，不从对话内容推测。

`kind` 仅接受上述候选事件中已验证的项目。未知事件忽略；必填字段不全或错误类型丢弃。原始输入最多 64 KiB，单个规范化事件最多 4 KiB。超过上限即忽略，不写入部分数据。

不保留原始 Hook 负载。提示词、回复、标题、工具参数、文件内容、完整路径、凭据与密钥不进入状态队列、诊断文件或通知文案。

按会话分隔 JSONL 队列，使用会话标识的 SHA-256 前 24 位作为文件名；不得将外部会话标识直接拼入路径。每会话保留最多两个 2 MiB 队列文件；最多跟踪 32 个会话。并发写入需通过本机文件锁串行化，50 ms 内取不到锁则放弃该次写入并正常退出。

读取器保留未结束的半行，检测文件替换、截断和轮换；处理损坏行时继续读取后续合法事件。已经处理的事件 ID 不重复触发提醒。

## 6. 状态与提醒

七种业务状态：`idle`、`thinking`、`working`、`waiting`、`review`、`done`、`failed`。另行显示连接状态 `disconnected` 或 `stale`，不将其伪装为空闲。

基础映射：用户提交进入思考；工具开始进入工作；工具结束回到思考；工具失败显示失败；已验证的审批事件进入等待审批；已验证的输入请求进入等待输入；主会话终止事件进入完成。`SessionEnd` 只标记会话结束，不独立触发“任务成功”。

需要通过会话阶段和活动工具集合处理乱序与迟到事件。已经终止的阶段不会被迟到的工具完成事件重新激活；新的用户提交开启新的阶段。可以使用已验证的轮次标识和事件时间过滤旧阶段事件；当源事件不包含足以关联轮次的字段时，在兼容性报告中注明限制，不宣称完全识别跨轮次乱序。子会话停止不得触发父会话完成。

跨会话显示优先级：等待审批 > 等待输入 > 失败 > 工作 > 思考 > 未读完成 > 空闲。每个终止阶段只通知一次；点击“已读”或新一轮用户提交可消除对应完成提醒。

完成提醒持续显示到确认，不根据窗口是否在前台推测已读。托盘通知不可用时，悬浮提示仍可用。点击“打开 WorkBuddy”唤起应用，不自动提交审批或回复。

## 7. 连接诊断与错误处理

诊断区分程序未找到、插件未安装、等待首个事件、已收到事件与运行中的状态过期。

未收到过事件时保持“等待连接”。已开始任务且连续 120 秒没有事件时显示“状态可能已过期”，不宣称任务完成；正在等待输入或审批的会话不因沉默而被改为断连。终止阶段保持完成状态，连接标记独立更新。

WorkBuddy 路径由用户选择或从已安装应用信息定位。禁止把不可信配置拼成 shell 命令。路径无效时提示重新选择；不以同名任意进程冒充 WorkBuddy。

界面不读取或上传 WorkBuddy 登录凭据。诊断仅记录版本、事件类型计数和能力结果；导出前能预览内容。

## 8. Windows 界面

一个透明悬浮角色窗口和一个独立状态气泡。默认角色大小约 160 像素，可在设置中调整。角色具有状态颜色、短标签和轻量动画；优先保证辨识度和低占用。

左键轻点唤起 WorkBuddy；超过 6 像素位移视为拖动。托盘提供显示/隐藏、连接诊断、设置、退出。设置包括 WorkBuddy 路径、角色大小、通知开关和位置重置。自启作为显式设置，首版默认关闭。

恢复位置时根据当前显示器可用区域限制坐标，避免断开外接屏后找不到桌宠。关闭设置窗口不退出后台桌宠；退出菜单正常释放队列读取器和 Qt 资源。

## 9. 验证与交付

自动化验证覆盖状态优先级、多会话和子会话、重复与迟到事件、半行与损坏行、轮换与截断、大小限制与字段投影、配置合并与卸载恢复、路径验证与坐标恢复。

使用合成事件的演示模式明确显示“演示”。Windows 实机验证至少包括思考、工具调用、完成提醒、等待审批、点击唤起和退出；若目标版本不提供某种事件，在诊断中显示能力缺失，不声称通过。

交付包含源码、中文使用说明、CI 测试和 Windows x64 程序包。发布前不把本机数据、日志、角色私有素材或凭据加入 Git。
